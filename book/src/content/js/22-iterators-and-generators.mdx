An **iterator** is an object that hands out values one at a time when you call its `next()` method. Anything that can produce an iterator is **iterable** — arrays, strings, `Map`, `Set` and many more. That is what `for...of`, spread (`...`) and destructuring use under the hood. A **generator** is a special function that makes writing iterators easy: it can **pause** at each `yield` and **resume** later from exactly the same spot.

<Analogy>
  An iterator is like a ticket dispenser at a deli counter: each pull gives you the next number, and it knows when it has run out. A generator is like a storyteller who stops at a cliffhanger each evening (`yield`) and picks up from the same sentence the next night (`next()`), remembering everything that happened so far.
</Analogy>

## Why it matters

These features power `for...of`, lazy data pipelines, paginated API clients and streams. Generators are also how `async/await` was first implemented, so understanding them shows you really know how suspension works. Async iterators (`for await...of`) are the modern way to consume streams in Node.

## The iteration protocol

Two small contracts:

- **Iterable:** an object with a `[Symbol.iterator]()` method that returns an iterator.
- **Iterator:** an object with a `next()` method returning `{ value, done }`.

```js
const it = ['a', 'b'][Symbol.iterator]();
it.next();  // { value: 'a', done: false }
it.next();  // { value: 'b', done: false }
it.next();  // { value: undefined, done: true }
```

### Making your own object iterable

```js
class Range {
  constructor(from, to) { this.from = from; this.to = to; }
  [Symbol.iterator]() {
    let current = this.from;
    const last = this.to;
    return {
      next: () => current <= last
        ? { value: current++, done: false }
        : { value: undefined, done: true },
    };
  }
}

for (const n of new Range(1, 3)) console.log(n);  // 1, 2, 3
[...new Range(1, 5)];                              // [1, 2, 3, 4, 5]
```

## Generators

A generator function is written with `function*`. Calling it **does not run the body**. It returns a generator object (which is both an iterator and an iterable). Each `next()` runs the body until the next `yield`, then pauses.

```js
function* range(from, to) {
  for (let i = from; i <= to; i++) {
    yield i;           // hand out i and pause here
  }
}

const gen = range(1, 3);
gen.next();   // { value: 1, done: false }
[...gen];     // [2, 3] — continues from where it paused
```

The `Range` class above shrinks to:

```js
class Range {
  constructor(from, to) { this.from = from; this.to = to; }
  *[Symbol.iterator]() {
    for (let i = this.from; i <= this.to; i++) yield i;
  }
}
```

### Two-way communication

The value you pass to `next(v)` becomes the **result of the paused `yield` expression** inside the generator.

```js
function* dialogue() {
  const a = yield 'first question';
  const b = yield `got ${a}, second question`;
  return a + b;
}
const d = dialogue();
d.next();        // { value: 'first question', done: false }   — runs to the first yield
d.next(10);      // { value: 'got 10, second question', done: false } — a = 10
d.next(20);      // { value: 30, done: true }                   — b = 20
```

That pause-and-resume ability, plus feeding values back in, is exactly what `async/await` needs: pause at `await`, and when the promise resolves, call `next(result)`. Before native `async` functions, libraries like `co` did precisely this with generators.

## Laziness

Generators only compute values when asked, so they can describe huge or even infinite sequences cheaply.

```js
function* naturals() {
  let n = 1;
  while (true) yield n++;     // infinite, but only runs on demand
}

function* take(iter, count) {
  for (const x of iter) {
    if (count-- <= 0) return;
    yield x;
  }
}

function* filter(iter, pred) {
  for (const x of iter) if (pred(x)) yield x;
}

[...take(filter(naturals(), (n) => n % 7 === 0), 3)];   // [7, 14, 21]
```

New built-in **iterator helpers** (`.map`, `.filter`, `.take`, `.toArray` directly on iterators) bring this style without writing generators: `naturals().filter((n) => n % 7 === 0).take(3).toArray()`.

## Async iterators and `for await`

An **async iterator**'s `next()` returns a **promise** of `{ value, done }`. `for await...of` consumes them, awaiting each step. Async generators (`async function*`) can both `await` and `yield`.

```js
async function* fetchAllPages(url) {
  let next = url;
  while (next) {
    const res = await fetch(next);
    const { items, nextPage } = await res.json();
    yield* items;              // hand out each item of this page
    next = nextPage;
  }
}

for await (const order of fetchAllPages('/api/orders')) {
  process(order);              // pages are fetched only as you consume them
}
```

Node streams are async iterable, which is the simplest way to read them line by line:

```js
import { createReadStream } from 'node:fs';
import { createInterface } from 'node:readline';

const lines = createInterface({ input: createReadStream('big.log') });
for await (const line of lines) {
  if (line.includes('ERROR')) console.log(line);
}
```

## Early exit and cleanup

If a `for...of` loop exits early (`break`, `return` or an error), it calls the iterator's `return()` method. In a generator, that runs any `finally` block — perfect for releasing resources.

```js
function* readRows(db) {
  const cursor = db.open();
  try {
    while (cursor.hasNext()) yield cursor.next();
  } finally {
    cursor.close();            // runs even if the consumer breaks early
  }
}
```

<Callout type="pitfall" title="Common mistakes">

- Expecting code before the first `yield` to run when the generator is created. It runs on the first `next()`.
- Iterating the same generator twice — it is single-use. Make the class iterable (`*[Symbol.iterator]`) to get a fresh one each time.
- Using `for...of` on a plain object — objects are not iterable. Use `Object.entries(obj)`.
- Forgetting that `for await` processes items one at a time — fine for streams, slow for independent requests.

</Callout>

## Explaining it in an interview

<InterviewAnswer question="What are generators, and how do they relate to async/await?">

A generator is a function declared with `function*` that can pause at `yield` and later resume. Calling it runs nothing; it returns an iterator, and each `next()` runs the body to the next `yield`, handing out a value. The argument to `next(v)` becomes the result of the paused `yield`, so data flows both ways, and local variables survive between calls. That is exactly what `async/await` needs: an async function is like a generator that yields promises, with a driver calling `next(result)` when each promise resolves. Generators are also great for lazy sequences and custom iterables, and async generators with `for await` are the clean way to consume paginated APIs and Node streams.

<Fragment slot="deeper">

- **What makes an object iterable?** A `[Symbol.iterator]` method returning an object with `next()`.
- **What does `return()` on an iterator do?** Signals early exit; in a generator it runs `finally` blocks.
- **Why are generators single-use?** They hold their own position; once completed, they stay completed.

</Fragment>
</InterviewAnswer>
